# Fixed variant — bounded local assurance

## Structural property

The public adapter cannot construct worker caller kind or identity. The separate worker adapter resolves a synthetic server-held registration, and the export effect requires a current grant bound to that worker, action, tenant, exact object set, expiry, and one successful sequential use. Missing, unknown, malformed, mismatched, expired, consumed, or evidence-failed state denies before output.

The fixed output contains only note `id` and `summary`. Decision events record bounded metadata and object count, not bodies or bearer grants. Under this exercise’s high-impact policy, unavailable evidence blocks export and leaves the grant unused.

## Honest independence claim

Public-adapter caller kind and server-held grant state are different decision inputs, so the controls are logically complementary for selected failures. They still share a Python runtime, process, fixture state, and operator. The fixture therefore classifies them as partially independent, not as two fully independent production layers.

## Assurance boundary

The tests establish only this local in-process behavior. The registration handle is a stand-in for a trusted adapter, not a credential or cryptographic workload identity. Grant consumption is sequential and in memory. The fixture does not prove networking/proxy behavior, queue semantics, persistent atomicity, database isolation, containers/sandboxing, egress control, durable evidence, operator/provider security, or ASVS compliance. Each introduction is a review trigger.
