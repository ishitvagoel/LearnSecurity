# Publishability bar (blueprint §16)

1. Begins with a security property or question, not a product command
2. Names attacker capabilities and trust assumptions
3. Distinguishes root cause, exploit preconditions, impact, prevention, detection, and recovery
4. Uses current canonical standards and labels maturity/status
5. Explains mechanism limits and common bypasses or failure modes
6. Contains a safe practice task and a transfer task
7. Tests forbidden outcomes and failure behavior
8. Separates framework defaults from application guarantees
9. Avoids universal claims where risk-based selection is required
10. Contains no live-target instructions or real sensitive data
11. Has executable code/labs verified in a clean environment
12. Tests usability and accessibility of security-sensitive journeys where human action is part of the control
13. Records reviewer and review date

## Mastery states (blueprint §10.2)

`not-attempted` | `developing` | `competent` | `transfer-ready`

Security-critical deficiencies cannot be hidden by high scores elsewhere.
