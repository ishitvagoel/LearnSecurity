### My own constructed fakes (methodology: build it, run it, watch it, then revert and verify clean)

**Fake #1 — hardcoded sink-independent "safe key" allow-list.** Replaced `fixed/app.py`'s `_redact` with:

```python
_REVIEWER_FAKE_1_SAFE_KEYS = {"event", "note_id", "company_id"}

def _redact(context: dict, sink: str) -> dict:
    out: dict = {}
    for key, value in context.items():
        out[key] = value if key in _REVIEWER_FAKE_1_SAFE_KEYS else "[redacted]"
    return out
```

This abandons `CLASSIFICATION` and `SINK_POLICY` entirely, and applies the identical hardcoded list to both sinks regardless of the `sink` argument. **Result: `python3 -m pytest labs/3.1/3.1-lab/tests --impl fixed` → 9 passed, 9 total. The suite did not catch this fake.** Restored via `git checkout -- labs/3.1/3.1-lab/fixed/app.py`; confirmed with a fresh `Read` that the file matched the original byte-for-byte, and `git status --porcelain` was empty.

Root-cause analysis of the miss: `application_log` and `error_dump`'s `SINK_POLICY` entries are both `{"internal"}` in this fixture — identical. No test in `test_property.py` exercises two sinks with *different* allowed levels, so nothing can distinguish "a per-sink policy correctly evaluated" from "one global hardcoded list applied everywhere," and this fake happens to be behaviorally indistinguishable from the correct mechanism for the five fields and two sinks this fixture currently has. It is not a case of an actually-insecure fix slipping through: the fake still fails closed for every field this fixture uses, including a fresh, never-seen `X-Debug-Hint` value (denied, because it's not in `_REVIEWER_FAKE_1_SAFE_KEYS`). It differs from the taught mechanism only in *shape* (hardcoded field names vs. a `CLASSIFICATION`-level indirection), which matters for maintainability (a new field would need updating at every sink's hardcoded list rather than being classified once) but does not, in this fixture, produce an observable security difference. I checked whether this is a promise the module breaks: `04-build.md`'s own Practice section already flags that a third sink might legitimately need a *different* policy (e.g. an audit export allowing Confidential), and `08-review.md`'s `candidate_fix.py` reading fixture does add such a differentiated third sink — but that fixture is explicitly not wired into `pytest` (confirmed by grep: `candidate_fix.py` is not imported anywhere under `tests/`). So this is a real, specific test-coverage gap, not a violated claim: nowhere does this module's own text assert that its **pytest suite** verifies genuine per-sink divergence. **Non-blocking finding, recorded below**, not a reason to withhold `depth: publishable`.

**Fake #2 — post-hoc regex redaction on known secret "shapes."** Replaced `log_event`/`write_error_dump` with:

```python
_REVIEWER_FAKE_2_SECRET_SHAPE = re.compile(r"(sess-[\w-]+|tenant-[\w-]+|secret)", re.IGNORECASE)

def log_event(event: str, context: dict) -> None:
    rendered = " ".join(f"{key}={value}" for key, value in context.items())
    rendered = _REVIEWER_FAKE_2_SECRET_SHAPE.sub("[redacted]", rendered)
    _LOG_LINES.append(f"{event}: {rendered}")
# write_error_dump analogous, per-field
```

This scrubs the *rendered* string for known secret-shaped substrings instead of checking classification per field before rendering — exactly the "regex-based redaction applied after the fact" limit `04-build.md` names in prose. **Result: `python3 -m pytest labs/3.1/3.1-lab/tests --impl fixed` → 2 failed (`test_unclassified_field_defaults_to_redacted`, `test_anti_fake_fresh_secret_not_a_literal_match`), 7 passed.** The suite correctly caught this fake: a freshly-generated random body (`note-body-<hex>`) and a freshly-generated random `X-Debug-Hint` value don't match the "known secret shape" regex and leaked, exactly as the anti-fake methodology is designed to catch. Restored via `git checkout -- labs/3.1/3.1-lab/fixed/app.py`; confirmed with a fresh `Read` that the file matched the original byte-for-byte, and `git status --porcelain` was empty after this restore too.
