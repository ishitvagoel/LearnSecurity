## Blockers

**1. `phase1_modules_for_learner`'s anti-fake test does not protect the property it exists to protect — a fake I constructed reproduces the module's own named forbidden outcome and passes all 15 tests, including the anti-fake test.** *(Safe executable lab — critical.)*

The shipped anti-fake test, `test_anti_fake_phase1_modules_fast_track_alone_does_not_drop_1_4`, calls `phase1_modules_for_learner(0, {}, fast_track=True)` — a **low** score paired with `fast_track=True`. It catches a fake that removes only the `quiz_score >= 80` branch while leaving `fast_track` alone able to drop `1.4` (I reproduced this exact result: 14 passed, 1 failed, the anti-fake test, matching the README's claim). But no test anywhere in the suite calls the function with **both** a high score **and** `fast_track=True` together. I constructed a fake that exploits exactly this gap:

```python
def phase1_modules_for_learner(quiz_score, tooling_gaps=None, fast_track=False):
    gaps = tooling_gaps or {}
    required = set(REQUIRED_PHASE1_MODULES)
    if quiz_score >= 90 and fast_track:      # AND instead of OR -- looks "safer"
        required.discard("1.4")
    bridge = {name for name, gap in gaps.items() if gap}
    return {"required": required, "bridge": bridge}
```

Installed as `fixed/diagnostic.py` and run against the real suite:

```
$ python3 -m pytest labs/0.2/0.2-bridge/tests --impl fixed -v
============================== 15 passed in 0.03s ==============================
```

**All fifteen tests pass, including the anti-fake test.** Yet this function still reproduces the module's own forbidden outcome exactly:

```
$ python3 -c "... mod.phase1_modules_for_learner(95, {}, fast_track=True) ..."
{'required': {'1.3', '1.2'}, 'bridge': set()}
```

`"1.4"` is dropped for a `quiz_score=95`, `fast_track=True` learner — the precise adaptive-path-hides-1.4 residual `03-break.md`, `spec.md`'s review triggers, and `module.yaml`'s `labSpec.forbiddenOutcomes` all name as this module's central thing to prevent. This is not a hypothetical: **the module's own assessment bank already constructs this exact AND-gated variant and correctly identifies it as still broken.** `items.md` #4 presents `if fast_track and quiz_score >= 90: required.discard("1.4")` as "a teammate proposes this fix, reasoning that requiring *both* ... is safer than either alone," and `keys/0.2.md`'s answer states plainly: "it is not a structural fix: it is a narrower version of the identical defect, still gated by `quiz_score` and `fast_track`, just requiring both instead of either." The module *teaches* that this fix is wrong, in a graded item, while its own executable lab cannot detect it if it were checked in as `fixed/diagnostic.py`. `05-verify.md` L38 states the standard this fails: "If your own edit to the fixed file makes both commands pass identically, you have not fixed anything — you have made the deny disappear from both variants, and the suite's job is to catch exactly that by disagreeing between them." My fake makes exactly one variant (a still-broken one) agree with `fixed/`'s expected behavior on every test in the file. Restored the original `fixed/diagnostic.py` from `HEAD` immediately after (`git status --porcelain` empty, `md5sum` matches the `HEAD` blob).

This also means the README's and `spec.md`'s claim that the anti-fake test was "verified by hand against a specific incomplete fake fix" is true only for the *one* fake shape that was checked (`fast_track` alone at a fixed low score) — the claim that this constitutes protection against "a narrow repair" in general (the framing `05-verify.md` and the README both use) overstates what was actually tested.

**To close:** add a test that calls `phase1_modules_for_learner` with `fast_track=True` **and** a high score together (e.g. `quiz_score=95, fast_track=True`) and asserts `"1.4" in result["required"]`. This single additional case would have caught my fake. Consider also naming, in `05-verify.md` or the README, that the hand-verified fake covered only the `fast_track`-alone shape, not an AND-gated combination — the same shape `items.md` #4 already treats as a live example of a plausible-but-wrong fix.
