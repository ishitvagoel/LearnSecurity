# Examiner notes — 0.1 (not learner-facing)

## Property

A URL is in scope only if it is a named local lab host (127.0.0.1, localhost, lab.securecollab.test). example.com, a employer production API, and a classmate’s deployed preview are out of scope even if they are “easy to hit.”

## Lab

- `labs/0.1/0.1-orientation/vulnerable/` must fail: HTTP to a non-allowlisted host treated as authorized
- `labs/0.1/0.1-orientation/fixed/` must pass.
- Root cause: Authorization collapsed into reachability: if TCP connects, it was treated as in-scope.

## Seeded review intended findings

- SECURITY.md says “any URL the proxy can open.”
- No stop condition when a redirect leaves 127.0.0.1.
- Live-target language in a learner note.
- Quiz score treated as permission to scan.

## Transfer

Reject answers that name Top 10 / CWE Top 25 items as the definition of security.
Require a system-specific invariant, attacker, trust, residual risk.
Acceptable transfer direction: Your company staging URL: what written artifact would make it in-scope? (Not a Slack thumbs-up.)

## Operate

Accept a detect/recover note that does not log bodies/secrets. Example signal: Denied-host log line {url, reason=out_of_scope}; never store response bodies from out-of-scope hosts.
