# Examiner notes — 1.4 (not learner-facing)

## Property

A high-impact recovery confirmation is a security control. If a legitimate user cannot complete it with keyboard, named controls, and a non-color cue, the control has failed (lockout or unsafe workaround). Residual risk is owned and dated, not a heat-map leftover. Coercion is residual, not deleted by CSS.

## Lab

- `labs/1.4/1.4-risk-register/vulnerable/` must fail `test_recovery_control_is_usable_and_accessible`
- `labs/1.4/1.4-risk-register/fixed/` must pass
- Root cause: designers trusted a pointer and a hue (psychological acceptability omitted)

## Seeded review intended findings

- Confirm button has no accessible name
- Destructive action distinguished only by red vs green
- Mouse-only drag-to-confirm
- Risk register lists residual as “users should be careful”

## Transfer

Reject Top 10 / CWE / scanner as the definition of security.
Require actor capability, trust, forbidden outcome, test idea, residual (including coercion), WCAG-as-baseline for the human path.
Acceptable direction: clinic mouse-only step-up; banking support read-aloud of OTP as a silent 1.2 change.

## Operate

Accept a detect/recover note that does not log codes or bodies. Example signal: modality and reason only.
Reject “email the password” as degrade.
