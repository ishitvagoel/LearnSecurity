# Examiner notes — 2.3 (not learner-facing)

## Property

A session cookie marked HttpOnly must not be readable by script in the lab DOM. That is a browser cell. It does not mean XSS is impossible (6.2) and does not make CSP3 or Trusted Types (Working Drafts) a substitute for encoding.

ASVS anchors: `v5.0.0-3.3.4` (HttpOnly for session tokens), `v5.0.0-3.3.1` (Secure). `v5.0.0-3.3.2` SameSite is a related purpose control, not this lab’s oracle.

## Lab

- `labs/2.3/2.3-browser-policy/vulnerable/` must fail `test_script_cannot_read_httponly_session`
- `labs/2.3/2.3-browser-policy/fixed/` must pass
- Root cause: session presented to the script interpreter

## Seeded review intended findings

- document.cookie used to persist session
- SECURITY.md equates HttpOnly with “no XSS”
- CSP Report-Only treated as enforcement (see E2)
- Missing Secure on the same cookie

## Transfer

Reject Top 10 / CWE as the definition of security.
Acceptable direction: clinic patient portal session; React Native WebView cookie bridge.
Require WCAG 2.2 only if a human-mediated control is in the rewritten claim.

## Operate

Accept a detect/recover note that does not log session values. Example: `Set-Cookie` without HttpOnly in staging scans; rotate if script could have read it.
