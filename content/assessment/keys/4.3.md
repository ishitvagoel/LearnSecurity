# Examiner notes — 4.3 (not learner-facing)

## Property

A session token in the query string is not an acceptable session. Cookie (HttpOnly, 2.3) or Authorization only. JWT is a format, not an architecture. TLS does not hide query from logs and Referer.

ASVS anchors: `v5.0.0-14.2.1`, `v5.0.0-3.4.5`, `v5.0.0-3.3.4`.

## Lab

- `labs/4.3/4.3-lab/vulnerable/` must fail `test_query_string_token_is_rejected`
- `labs/4.3/4.3-lab/fixed/` must pass, including cookie and Authorization happy paths
- Root cause: token placed in a logged, shared channel

## Seeded review intended findings

- session_from_request uses query
- JWT in localStorage as “SPA best practice” 2016 blog
- No Referer policy
- Tokens printed in uvicorn logs

## Transfer

Reject Top 10 / CWE as the definition of security.
Acceptable direction: clinic appointment deep link; magic-link email (time-bound, one-time, 6.6) exchanged for a cookie.
WCAG if a human must follow the link.

## Operate

Accept detect/recover that does not log the token. Example: `query_token_rejected` plus path; revoke; purge logs.
Reject “HTTPS so the query is fine.”
